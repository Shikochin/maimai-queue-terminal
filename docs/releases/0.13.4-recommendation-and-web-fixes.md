# maimai Q 0.13.4 网页与玩家资料推荐修复

maimai Q 0.13.4 修复手机二维码创建玩家资料的首屏空白，统一跨设备的中点分隔符显示，并重新设计现场终端玩家资料库的推荐排序。现场终端与本地版为 `0.13.4`（构建号 `70`），网站和服务端最新版本为 `0.13.4`，管理 App 继续使用独立版本 `0.13.1`（构建号 `67`），QQ Bot 保持 `0.3.13`。

## 手机二维码创建页

- 创建页通过 Teleport 挂载到 `body` 后固定覆盖视口，不再受原队列页面 `min-height: 100vh` 的空白占位影响。
- 页面支持上下滚动，保留 Android 刘海和手势区域的安全内边距；`390×844` 与 `360×640` 浏览器验收均无需先滚动即可看到页头和表单。

## 中点分隔符

- 规范纯文本使用不带额外空格的 `甲·乙`，终端、管理后台、网站和服务端读取时会清理历史字符串两侧空白。
- 队列标题等结构化富文本不再依赖字体中的中点字形来承担布局间距，而是使用独立 CSS 圆点，避免系统字体差异造成视觉距离不一致。
- Android 旧协议 1 至 7 的兼容字段仍按原格式生成；新协议与用户界面采用紧凑格式。

## 玩家资料推荐

推荐模式现在使用可解释的多因素排序，而不是按累计次数硬排序：

- 每次使用会保存最近最多 16 个时间点；近 90 天的事件按 14 天半衰期衰减，重复的近期使用会产生叠加权重。
- 创建后 14 天内的新资料会获得从高到低逐步消退的发现加权，长期未使用后自动失效。
- 累计游玩次数只按 `log1p` 计算并封顶，作为熟悉度补充；最后使用时间只提供小幅新鲜度补充。
- 搜索时精确昵称/编号优先，其次是前缀，再按包含匹配；同一匹配层内才比较推荐分。最后使用时间、创建时间、中文昵称和资料 ID 用于稳定打破平局。
- 未来时间戳按当前时间处理，不会获得无限推荐分；旧资料没有近期时间序列时仍可正常显示，并从之后的新使用开始积累。

服务端数据库会自动增加 `player_profile.recent_usage_at` 字段。旧终端不发送该字段时，服务端保留已存历史并继续接受旧快照；新终端发送的历史最多保留 16 条，避免资料快照无限增长。
